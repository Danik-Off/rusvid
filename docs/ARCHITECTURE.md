# Архитектура

## Идея в одном абзаце

Приложение — это **агрегатор**: тонкий UI поверх нескольких взаимозаменяемых
видеоплатформ. Всё, что специфично для платформы, спрятано за интерфейсом
`VideoProvider`. UI не знает ни одного поля Rutube, VK или Sasflix — он
работает только с доменной моделью (`VideoSummary`, `PlaybackSource`, `Page`).

---

## Слои

```
┌─────────────────────────────────────────────────────────┐
│  app/        композиция: контейнер, навигация, App       │
├─────────────────────────────────────────────────────────┤
│  features/   экраны + zustand-сторы (feed, search,       │
│              player, library, settings, auth,            │
│              diagnostics)                                │
├─────────────────────────────────────────────────────────┤
│  ui/         дизайн-система: токены, Icon, Button,       │
│              VideoCard, VideoList, ChipRow, Skeleton     │
├─────────────────────────────────────────────────────────┤
│  core/       доменная модель, контракт провайдера,       │
│              агрегатор, спецификация авторизации, ошибки │
├─────────────────────────────────────────────────────────┤
│  providers/  реализации платформ: rutube / vk / sasflix  │
├─────────────────────────────────────────────────────────┤
│  data/       HTTP-клиент, кэш, хранилище, репозитории    │
└─────────────────────────────────────────────────────────┘
```

**Правило зависимостей — сверху вниз.** `core/` не импортирует ничего из
`features/`, `ui/` или `providers/`. `providers/` зависит от `core/` и `data/`,
но никогда — от UI. Это то, что позволяет добавить платформу, не трогая экраны.

### Что где лежит

| Каталог | Содержимое |
|---|---|
| `src/core/model/` | `VideoSummary`, `VideoDetails`, `PlaybackSource`, `Page`, `Cursor` |
| `src/core/provider/` | `VideoProvider`, `ProviderRegistry`, `ProviderAuthSpec` |
| `src/core/aggregator/` | `AggregatorService` — веерный опрос платформ |
| `src/core/errors/` | `ProviderError` с кодами и русскими сообщениями |
| `src/data/http/` | `HttpClient`: таймаут, ретраи, нормализация ошибок |
| `src/data/cache/` | `TtlCache` с дедупликацией параллельных запросов |
| `src/data/storage/` | обёртка над AsyncStorage + in-memory реализация для тестов |
| `src/data/{settings,library,credentials}/` | репозитории настроек, истории/избранного, учётных данных |
| `src/providers/<id>/` | `<Id>Provider.ts`, `<id>ApiTypes.ts`, `<id>Mappers.ts` |
| `src/providers/shared/` | общее для платформ: `WebSessionGuard`, `userAgent`, `webSession` |
| `src/features/<name>/` | экран + его store |
| `src/specs/` | спецификации собственных нативных модулей (кодогенерация) |
| `src/app/container/` | composition root |

## Ключевые решения

### 1. Провайдер как единственная точка расширения

```ts
interface VideoProvider {
  readonly meta: ProviderMeta;
  readonly capabilities: ProviderCapabilities;
  readonly auth: ProviderAuthSpec;
  isConfigured(): boolean;
  search(request, context): Promise<Page<VideoSummary>>;
  feed(request, context): Promise<Page<VideoSummary>>;
  getDetails(id, context): Promise<VideoDetails>;
  resolvePlayback(request, context): Promise<PlaybackSource>;
  listCategories?(context): Promise<readonly Category[]>;
}
```

`capabilities` — не украшение: агрегатор по ним решает, кого спрашивать.
VK объявляет `trendingFeed: false`, и лента его просто не опрашивает, а не
получает исключение. Добавление платформы = новый каталог + одна строка в
`src/providers/registerProviders.ts`. Чек-лист — [PROVIDERS.md](PROVIDERS.md).

### 2. Деградация вместо падения

`AggregatorService` опрашивает платформы через `Promise.allSettled`. Если VK
вернул протухший токен, а Rutube и Sasflix ответили — пользователь видит
результаты двух платформ и жёлтую полосу «VK: токен недействителен». Полный
отказ экрана возможен только когда упали все.

### 3. Независимая пагинация

У каждой платформы свой курсор (`CursorMap`). Rutube считает страницами,
VK — offset'ами, Sasflix — страницами со своим лимитом; агрегатор в содержимое
курсора не заглядывает. Курсор `null` означает «страницы кончились» — на
следующей подгрузке платформа не опрашивается вовсе.

### 4. Round-robin слияние

Результаты платформ перемешиваются по кругу (`interleave`), иначе Rutube
с его сотнями результатов занял бы весь первый экран, а Sasflix никто бы
не увидел.

### 5. Ссылки на поток не кэшируются

Rutube отдаёт **подписанный** URL с полем `expire`. Он запрашивается в момент
открытия плеера и не попадает ни в кэш, ни в историю. В `TtlCache` кладутся
только «дешёвые и долгоживущие» ответы: списки категорий, детали топиков.

### 6. Воспроизведение: два подводных камня ExoPlayer

Оба стоили полной неработоспособности плеера, и оба неочевидны, потому что
сборка при них проходит успешно.

**а) Модули ExoPlayer подключаются флагами, и все они выключены по умолчанию.**
`react-native-video` собирает список зависимостей так:

```groovy
[(property): safeExtGet(property)?.toBoolean() ?: false]   // ← default: false
```

Нет `RNVideo_useExoplayerHls=true` в `android/gradle.properties` — нет
`media3-exoplayer-hls` в APK — не играет ни Rutube, ни Sasflix. Флаг задан
и прокомментирован в `gradle.properties`; не удаляйте его.

**б) Формат потока ExoPlayer определяет по расширению в пути URL.**
У Rutube манифест лежит по `…/xxx.m3u8?sign=…` и распознаётся, а у Sasflix —
по `https://sasflix.ru/api/video/{uuid}` **без расширения** (Content-Type
`audio/mpegurl` при этом верный, но в определении формата не участвует).
Без подсказки такой источник уходит в progressive-ветку и падает, поэтому
`PlayerSurface` всегда передаёт явный тип:

```tsx
source={{ uri, type: source.kind === 'hls' ? 'm3u8' : undefined, headers }}
```

**в) Сбой плеера обязан быть виден.** `onError` ExoPlayer и `onError` /
`onHttpError` WebView приводятся к тексту и уходят в
`usePlayback.reportPlaybackFailure`. Если у платформы есть встроенный плеер,
приложение переключается на него; если нет — показывает ошибку с кнопкой
«Повторить». Состояния «чёрный прямоугольник без объяснений» быть не должно.

### 7. Авторизация как данные

Провайдер объявляет `auth: ProviderAuthSpec` — либо `{ kind: 'none', reason }`,
либо `OAuthSpec` с методами `buildAuthorizeUrl` / `extractToken` /
`extractError`. `SettingsScreen` и `AuthScreen` универсальны: они читают
спецификацию и не содержат ни одного `if (providerId === 'vk')`.

VK-вход реализован как Implicit Flow во встроенном WebView: пароль вводится
на странице VK и через код приложения не проходит — мы видим только токен
в редиректе на `blank.html`. Обоснование и инструкция —
[PROVIDERS.md](PROVIDERS.md#авторизация).

### 8. Самопроверка платформ

Экран «Проверка платформ» прогоняет по каждой включённой платформе живую
цепочку `конфигурация → поиск → лента → категории → ссылка на видео`,
замеряет время и показывает текст ошибки на конкретном шаге. Это ответ на
главный риск проекта: три недокументированных API, которые могут измениться
в любой день. Вместо «ничего не работает» пользователь получает
«Sasflix, шаг „Ссылка на видео“: HTTP 404».

### 9. Единая модель ошибок

Провайдеры не выпускают наружу `TypeError` из `fetch` или сырые HTTP-коды —
всё превращается в `ProviderError` с кодом (`AUTH_REQUIRED`, `TIMEOUT`,
`GEO_BLOCKED`, …), русским сообщением и флагом `isRetryable`. UI решает,
показывать ли кнопку «Повторить», по флагу, а не по тексту.

### 10. Composition root

Весь граф зависимостей собирается в `src/app/container/AppContainer.ts`.
Экраны и сторы берут зависимости оттуда, а не создают сами; в тестах граф
подменяется через `setAppContainer()`.

## Дизайн-система

Все цвета, отступы, радиусы, типографика и тени живут в `src/ui/theme.ts`;
литералов цвета в компонентах нет. Палитра — холодный нейтральный ряд с
единственным акцентом: платформы уже приносят свои фирменные цвета в
карточки, и второй акцент интерфейса конфликтовал бы с ними.

Иконки — векторные пути (`src/ui/components/Icon.tsx`), а не юникодные глифы:
глиф рисуется системным шрифтом и выглядит по-разному на каждой прошивке.
Сетка 24×24, толщина штриха 1.8.

Ожидание списка показывается скелетонами, повторяющими геометрию карточки,
а не спиннером — при появлении данных ничего не «прыгает».

## Поток данных: поиск

```
SearchScreen
   └─ useSearchStore.submit(query)
        ├─ отменяет предыдущий AbortController
        ├─ registry.active(enabledProviders)   ← настройки пользователя
        └─ aggregator.search(query, { providers, cursors, signal })
             ├─ Promise.allSettled по провайдерам
             │    ├─ RutubeProvider.search  → HttpClient → mapRutubeVideoList
             │    ├─ VkProvider.search      → VkApiClient → mapVkVideoList
             │    └─ SasflixProvider.search → HttpClient → mapSasflixTopicList
             └─ interleave(результаты) + cursors + failures
```

Каждый новый поиск отменяет предыдущий: пользователь печатает быстрее, чем
отвечает сеть, и «догнавший» старый ответ подменил бы выдачу.

## Поток данных: воспроизведение

```
экран списка → usePlayerStore.open(video, список как очередь «Далее»)
   │
PlayerOverlay (живёт НАД навигатором, монтируется один раз)
   ├─ usePlayback(current) → provider.resolvePlayback({ id, preferEmbed }, ctx)
   │     ├─ 'hls' | 'progressive' → react-native-video (ExoPlayer, type: 'm3u8')
   │     └─ 'embed'               → react-native-webview (плеер платформы)
   │          ↑
   │          └── сюда же уходим автоматически, если ExoPlayer сообщил об ошибке
   ├─ PlayerSurface   — единственный <Video> на весь сеанс
   ├─ PlayerControls  — свои элементы управления и жесты поверх кадра
   └─ PlayerDetails   — описание, действия, очередь «Далее»
```

### 6.1. Почему плеер не экран, а оверлей

Плеер намеренно **не** входит в `RootStackParamList`. Экран стека
размонтируется на «назад» — вместе с ним умирал бы `<Video>`, обрывался звук
и терялась позиция, а «свернуть и продолжить листать ленту» было бы
невозможно в принципе.

Поэтому `PlayerOverlay` — сосед `NavigationContainer` в `App.tsx`, а режимы
`mini` / `full` / `fullscreen` — это анимация геометрии **одного и того же**
поддерева, а не разные ветки рендера. Отсюда же требование к коду оверлея:
полноэкранный режим меняет стили, но никогда не рендерит `<Video>` в другом
месте дерева.

Из того же следует пара неочевидных обязательств:

- **Источник обязан быть мемоизирован.** `PlayerSurface` перерисовывается
  дважды в секунду (позиция), а `react-native-video` считает новый объект
  источника новым видео — без `useMemo` поток переоткрывался бы на каждом тике.
- **Позиция сохраняется по таймеру, а не при размонтировании.** Раньше
  `PlayerScreen` писал позицию в `useEffect`-cleanup, а при открытии
  затирал её нулём. Теперь `libraryStore.noteProgress` троттлит запись
  (2 с в память, 10 с на диск) и дожимается на паузе, при закрытии плеера
  и в `AppState !== 'active'`.

## Состояние

`zustand` — независимые сторы, по одному на область:

| Store | Отвечает за |
|---|---|
| `settingsStore` | включённые платформы, учётные данные, флаги приватности/плеера |
| `feedStore` | лента: область (все/платформа), категория, страницы |
| `searchStore` | запрос, результаты, курсоры, сбои платформ |
| `playerStore` | что играет, очередь, режим, скорость, дорожки, таймер сна |
| `libraryStore` | история просмотров и избранное |
| `searchHistoryStore` | недавние поисковые запросы |
| `updatesStore` | проверка релизов на GitHub |
| `diagnosticsStore` | отчёты самопроверки платформ |

**Подписка на пометки списков — только через `useLibraryMarks()`.**
`useLibraryStore((s) => s.progressOf)` возвращает ссылку на функцию, которая
никогда не меняется: экран не перерисуется при изменении истории, и полоски
досмотра на карточках замрут. Хук подписывается на сами данные.

`playerStore` — единственный, кто зовёт `libraryStore` напрямую: позиция
просмотра рождается в плеере, а живёт в библиотеке, и промежуточный слой
здесь был бы лишним звеном ради самого слоя.

## Edge-to-edge и системные полосы

`edgeToEdgeEnabled=true` в `gradle.properties` означает, что приложение
рисуется **под** статус-баром и панелью навигации. Отсюда два правила, оба
были нарушены и оба давали один и тот же баг — контент под клавишами
«назад / домой / меню»:

1. **Ни одна панель не задаёт высоту числом.** Только «база + системный
   inset» (`src/ui/layout.ts`). Жёсткая `height` в `tabBarStyle` отменяет
   отступ, который react-navigation берёт из safe-area.
2. **Списки знают, сколько занято снизу.** `useBottomSpace()` складывает
   таб-бар, системную навигацию и свёрнутый плеер; результат уходит в
   `contentContainerStyle.paddingBottom`.

Плюс `values-v29/styles.xml` отключает `enforceNavigationBarContrast` —
иначе система подкладывает под панель навигации серую подложку поверх
тёмного интерфейса.

Сторы не знают друг о друге напрямую; `feedStore` и `searchStore` читают
список включённых платформ через `useSettingsStore.getState()` в момент
запроса — так они всегда работают с актуальными настройками.

## Осознанные компромиссы

- **Токены в AsyncStorage, не в Android Keystore.** Данные лежат в приватном
  каталоге приложения (недоступны другим приложениям на не-root устройстве),
  но не шифруются. Для перехода на Keystore достаточно подменить реализацию
  `KeyValueStore` в `CredentialsStore` — интерфейс это допускает.
- **Своё приложение VK вместо чужого app id.** Технически можно было бы
  зашить client_id официального клиента и избавить пользователя от лишнего
  шага. Не сделано намеренно: это выступление от чужого имени.
- **Одна тема (тёмная).** Светлая потребовала бы второго набора токенов;
  для видеоприложения тёмная уместнее, а один набор проще держать
  согласованным.
- **Нет офлайн-загрузки видео.** Кэшируются только метаданные.
- **`ProviderId` — закрытый union.** Добавление платформы требует правки
  одной строки в `PROVIDER_IDS`. Взамен получаем полную проверку типов
  во всех `Record<ProviderId, …>`.

## Тесты

`npm test` — 60 юнит-тестов, без сети и без нативных модулей:

- `AggregatorService` — перемешивание, деградация при падении платформы,
  пропуск исчерпанных курсоров, отказ ходить в сеть на пустом запросе;
- `HttpClient` — сборка URL, ретраи только на повторяемых ошибках,
  маппинг HTTP-кодов, отказ идти в сеть по отменённому сигналу;
- `vkAuth` — сборка URL авторизации, разбор токена и ошибки из редиректа;
- мапперы всех трёх платформ на **реальных** ответах API;
- `LibraryRepository` — схлопывание повторов, обрезка по лимиту;
- `normalizeSettings` — миграция настроек со старых версий;
- форматирование дат/чисел, включая русские склонения.

### Живой смоук-тест

Отдельный набор ходит в настоящие API Rutube и Sasflix — проверяет, что
чужие эндпоинты ещё живы и схема не поменялась. По умолчанию пропускается:

```powershell
$env:RUSVID_LIVE = '1'; npm test -- live.smoke
```

Он проверяет поиск, ленту, категории и **фактически скачивает HLS-манифест**,
убеждаясь, что тот начинается с `#EXTM3U`. VK в набор не входит: нужен
пользовательский токен. Тот же прогон в рантайме доступен пользователю —
экран «Проверка платформ».
